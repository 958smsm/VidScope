# Phase 0 repository and toolchain assessment

## Repository state

`D:\Projects\Repos\VidScope` was created as a new project root. It contained
no prior source, build system, application architecture, dependencies, tests,
or user-authored functionality to preserve. The implementation therefore uses
the directory structure and dependency direction documented in
`architecture.md` without reorganizing another project.

## Detected development environment

- Windows x64
- CMake 4.1.2
- Visual Studio Enterprise 2026 / MSVC 14.50.35717
- Ninja from `D:\dev\Qt\Tools\Ninja\ninja.exe`
- Qt 6.11.2, MSVC 2022 x64 package
- FFmpeg shared development build N-118472 (libavformat/libavcodec 61,
  libavutil 59), including D3D11VA/DXVA2 and GPL codecs

The installed CMake release does not expose a Visual Studio 18 generator, so
the reproducible Windows preset uses Ninja Multi-Config inside the Visual
Studio developer shell.

## Architecture consequences

- FFmpeg 61 APIs are used directly; removed legacy `AVFrame` fields are not
  referenced.
- D3D11VA is attempted first on Windows, but transferred software surfaces and
  CPU decode remain the correctness path for Phase 2.
- Synthetic fixtures are generated by the detected FFmpeg CLI at test time,
  avoiding checked-in binary test assets.
- The detected FFmpeg distribution is GPL-enabled; binary distribution needs
  a deliberate project-license decision.
